### 1. JSON-LD in `<script>` — possible script breakout (XSS)

**Where:** Output of stored JSON-LD in `wp_head` (e.g. around lines 6692–6695 and 7238).

**Issue:** Stored JSON-LD is echoed directly inside `<script type="application/ld+json">`. If an admin (or compromised account) saves content that includes `</script>`, it can break out of the script tag and run code in the page.

**Fix:** Before echoing, escape the sequence that closes the tag:

```php
$jsonld_safe = str_replace( '</script>', '<\/script>', $jsonld );
echo '<script type="application/ld+json">' . $jsonld_safe . "</script>\n";
```

Or decode, validate structure, and re-encode with `wp_json_encode()` so output is always safe JSON.

**Severity:** Low (requires edit capability; content is stored, not reflected from URL).

### 1. CSRF — Create/revoke token forms have no nonce

**Where:** `ocml_admin_page()` handles `ocml_create_token` and `ocml_revoke_token` (lines 46–58).

**Issue:** Actions depend only on POST and `current_user_can( 'manage_options' )`. There is no `wp_nonce_field` / `check_admin_referer`, so a logged-in admin could be tricked (e.g. via malicious link/form) into creating or revoking tokens.

**Fix:**

- Add nonce to both forms, e.g. `wp_nonce_field( 'ocml_admin', 'ocml_nonce' );`.
- Before handling create/revoke, verify:  
  `if ( ! isset( $_POST['ocml_nonce'] ) || ! wp_verify_nonce( $_POST['ocml_nonce'], 'ocml_admin' ) ) { wp_die( 'Security check failed.' ); }`

**Severity:** Medium (admin-only, but CSRF is a standard hardening).

### 2. Permalink output — escape for HTML/attributes

**Where:** Line 90 — permalink in `href` and link text.

**Issue:** `get_permalink()` is used in attributes and text without `esc_url()` / `esc_html()`.

**Fix:**

```php
$permalink = get_permalink( $page->ID );
echo 'Permalink: <a href="' . esc_url( $permalink ) . '" target="_blank">' . esc_html( $permalink ) . '</a>';
```

**Severity:** Low (permalink is usually safe; escaping is best practice).

### 1. Allowlist POST action (hardening)

**Where:** Lines 254–258 — `$_POST['ppsc_action']` is compared to `clear_all`, `clear_one`, `preload_all`.

**Issue:** After nonce check, the code only does string comparison. Allowlisting the value avoids any ambiguity if the request is malformed.

**Fix:**

```php
if ( isset( $_POST['ppsc_action'] ) && check_admin_referer( 'ppsc_cache_action', 'ppsc_nonce' ) ) {
    $action = $_POST['ppsc_action'];
    if ( $action === 'clear_all' ) {
        $this->clear_all_cache();
    } elseif ( $action === 'clear_one' && isset( $_POST['ppsc_post_id'] ) ) {
        $this->clear_single_cache( intval( $_POST['ppsc_post_id'] ) );
    } elseif ( $action === 'preload_all' ) {
        $this->preload_all_cache();
    }
}
```

(Or use `in_array( $action, array( 'clear_all', 'clear_one', 'preload_all' ), true )` and then switch/call.)

**Severity:** Low (nonce already blocks unauthorized requests).
